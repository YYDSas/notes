## 怎么用这套题库

### 刷题顺序建议

```plain
第 1 轮（建立框架，2~3 天）
  UVM 平台与组件 → factory 与配置 → 相位与 objection → TLM 通信
  ↑ 这四篇是"平台怎么搭起来"，必须先通

第 2 轮（核心机制，3 天）
  UVM 序列与仲裁 → 寄存器模型 RAL
  ↑ 这两篇是 UVM 面试的最大考点，也是实际工作中最常问的

第 3 轮（语言基础，3~4 天）
  SV 语言基础 → 覆盖率与断言
  ↑ SV 语言题最多也最容易踩坑，务必自己动手敲一遍代码

第 4 轮（扩展知识，2 天）
  数字电路与时序设计 → 总线协议 AHB APB AXI
  ↑ 验证岗的"硬骨头"，答不上来会显得基础薄

第 5 轮（项目包装，2 天）
  项目与综合面 → 验证方法与流程
  ↑ 必须结合自己项目改写，纯背没用
```

### 答题四段式

1. **先给结论**（一句话，面试官问的就是这个）
2. **再讲机制**（"为什么这样设计"，体现你理解原理而不是背答案）
3. **补代码/表格**（有代码就写 3~5 行关键代码，别写一整页）
4. **最后补边界条件或坑**（这一步最能加分）

例：问"m_sequencer 和 p_sequencer 的区别"

```plain
❌ "m_sequencer 是成员变量，p_sequencer 是……就是那个宏……"       （背，没理解）

✅ 结论：m_sequencer 是 uvm_sequencer_base 类型的成员句柄，
        指向启动本 sequence 的 sequencer；但因为类型是父类，
        直接访问子类自定义成员会编译报错，要先 $cast 向下转型。
        p_sequencer 就是用 `uvm_declare_p_sequencer 宏声明的成员变量，
        宏帮你自动完成这个 cast，所以可以直接访问子类成员。
   机制：sequence 挂到 sequencer 上时，sequencer 句柄被赋给 m_sequencer
        （向上转型，所以类型是 uvm_sequencer_base）。
   代码：`uvm_declare_p_sequencer(my_sequencer)
   坑  ：也可以手写 if (!$cast(p_sequencer, m_sequencer))
             `uvm_fatal(...) —— 转型失败要主动报错，
        否则运行期会出现空的 p_sequencer，访问成员时报空引用。
```

## 资料里几个值得注意的"坑点"

这些是四份资料里容易被忽略但面试官爱追问的细节：

- **`uvm_top.get_full_name()` 返回空串**，不是 `"uvm_top"`。
- **`component` 一般在 `build_phase` 例化，`object` 可以在任何 phase 例化**。在 `new()` 里例化 component 会导致上层配置失效。
- **TLM 的 port/export/imp 不是 `uvm_component` 子类**，要用 `new()` 而不是 `create()`。
- **`pre_body`/`post_body` 只有 `start` 启动才调**，`uvm_do` 宏不调。
- **`start_item` 和 `finish_item` 之间不能加延迟**，会占住 sequencer。
- **`update()` 方向是期望值→DUT，`mirror()` 方向是 DUT→镜像值**。
- **自动预测的盲区**：绕过 reg 模型直接在总线上操作的 sequence。
- **多 bit 信号不能跨时钟域打两拍**（只有单 bit 可以）。
- **格雷码前提是满 2^n 范围**：3 bit 必须 0~7，0~6 不行。
- **AXI 没有独立读响应通道**，`RRESP` 搭在读数据通道里。
- **AXI4 取消 `WID`** 是为了避免乱序带来的死锁和 buffer 浪费。
- **`PSTRB` 在读操作中必须全 0**。
- **前仿查不出亚稳态/竞争冒险/保持时间**，也查不出性能效率差异。
