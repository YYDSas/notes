# 面试题 · 总线协议 AHB / APB / AXI

> 汇总自《面试总结》总线部分第 1~19 题。验证岗面试高频，尤其是 AXI。

## 1. AHB / APB / AXI 各有哪些信号？

```text
AHB：clk, rstn, addr, pwrite, wdata, rdata, trans, burst, sel, port, size, resp, ready（13 个）
APB：clk, rstn, addr, sel, pwrite, wdata, rdata, enable, ready, slverr（10 个）
AXI：比较重要且独有的 last_valid、len
```

### AXI 关键信号含义

| 信号 | 含义 |
| --- | --- |
| `Size` | 突发传输中**每个 transaction 的大小**，单位 byte |
| `Burst` | 突发类型：固定长度 / 增量 / 回环 |
| `Len` | 突发长度，一次突发传输中 **transaction 的个数** |
| `Last` | 突发传输的**最后一个 transaction** |
| `ID` | 每笔传输的 transaction ID 号 |
| `Valid` | 表示读/写数据和选通信号有效 |

## 2. AHB / APB / AXI 的区别？

1. **定位**：AHB 是先进的高性能总线；AXI 是**先进可扩展接口**；APB 用于**低带宽且不需要流水线操作**的高性能外围设备。
2. **通道**：AHB 和 APB 都是**单通道总线**，不支持读写并行；**AXI 是多通道总线**，共 5 个通道，能实现读写并行。
3. **主从**：AHB 和 AXI 都是**多主/多从**、有仲裁机制；**APB 是单主多从，不具有仲裁机制**。
4. **数据操作**：AHB 和 AXI 支持**突发传输**，APB 不支持；AXI 支持**非对齐**数据操作，AHB 不支持。
5. **位宽**：AXI 最大支持 **1024**，AHB 最大支持 **256**，APB 最大支持 **32**。

### AHB vs APB

1. AHB 先进的高性能总线，APB 用于低带宽且不需要流水线总线接口的高性能外围设备
2. AHB 支持**二级流水线**，APB 不支持
3. AHB 有**仲裁机制**，APB 没有
4. AHB 多主/多从，APB 单主多从
5. AHB 支持突发传输，APB 不支持
6. 最大总线宽度不同：AHB 256，APB 32

## 3. APB2.0 / 3.0 / 4.0 的区别？

**APB2.0 → APB3.0**：提供了低功耗接口，降低了接口复杂性，增加两个信号：

- **`PREADY`**：扩展 APB 传输，主要用于**增加延时**
- **`PSLVERR`**：指示**传输失败**

**APB3.0 → APB4.0**：增加了 `PROT` 和 `PSTRB` 两个信号：

- **`PPROT`**：保护信号，支持 APB 上的**非安全交易和安全交易**
- **`PSTRB`**：一个**写读选通信号**

## 4. 为什么 APB 发送数据需要两个周期？

因为 APB 用在**低速设备的外围**，不需要像 AHB 那样两段流水——即不能在数据传输周期同时在总线上发送第二个数据的地址。

## 5. AHB 发送一个 trans 最少几个周期？

**2 个。**

## 6. AHB 发送一个 single 数据时，如果 READY 信号拉低 3 个周期，一共几拍？

**4 个。**（1 拍地址 + 3 拍等待）。

## 7. AHB 的 HTRANS 传输类型有哪几种？

| HTRANS[1:0] | 类型 | 说明 |
| --- | --- | --- |
| `00` | **IDLE** | 主设备空闲总线。用 2'bxx 传输命令或主设备响应 BLE。IDLE 表示没有 slave 响应，**需注意 BLE**。如果从设备希望立刻响应，需产生 slave ready |
| `01` | **BUSY** | 主设备忙，处于存取操作 / 等待响应 / 预取数据。一段 burst 传输中断处于数据预取或预取传输数据过程，通过 HREADY 返回一个 OKAY 响应 |
| `10` | **NONSEQ** | 一次**非连续**的地址传输——3（burst 传输）的**第一个数据**，地址和控制信号与上一拍传输相关 |
| `11` | **SEQ** | burst 传输**接下来的数据**，地址和上一次传输的地址相关 |

## 8. AHB 的 burst 类型有哪几种？

- **递增传送**：依上一笔的地址来递增
- **回环传送（wrap）**：如回环长度为 4，每 4 个字节对齐在 16 字节范围内。如果第一个地址 = `0x64`，则回环顺序为 `0x68`、`0x6C`、`0x6E`

## 9. AHB 的拆分事务（split transaction）是什么意思？

slave 的 split 传输：当某个 master 和 slave 传输时，占用了总线所有权，但**占着地方不办事儿**。

此时 slave 返回一个 **split 信号**结束这次访问，换到别的 master 来访问这个 slave。这个信号给到仲裁器后，会让该 master 对这个 slave 的**优先级变为最低**，且一直保持低，直到对这个 slave 的数据访问结束，才恢复到最初的优先级。

## 10. AHB 为什么要跨 1KB 边界？怎么做？

burst 传输**不能跨越 1KB 边界**，因为 slave 的地址空间都是以 1KB 为单位的——这样做是为了让一个单独的 burst **不能访问多个 slave**。

**避免越界的方法**：当 `trans` 信号走到 1KB 地址边界时，改成 **NON_SEQ**，重新发起一次 burst 传输。

## 11. AXI 有几个通道？每个做什么用？

**5 个通道**：

| 通道 | 作用 |
| --- | --- |
| **读和写地址通道**（AWADDR / ARADDR） | 传输一次数据所需的**地址和控制信息** |
| **读数据通道**（RDATA） | 从机向主机返回**读数据和读响应信息** |
| **写数据通道**（WDATA） | 主机向从机传输**写数据** |
| **写响应通道**（BRESP） | 从机通过它返回**写响应信息** |

## 12. 为什么 AXI 没有读响应通道？

因为**读响应信息 `RRESP` 可以作为读数据通道的一部分传递**。

> 记住：AXI 有独立的**写响应**通道（B），但**没有**独立的读响应通道。

## 13. AXI 的 4KB 边界是什么？为什么不允许跨越？

**4KB 边界**：指**低 12 bit 为 0** 的地址，例如 `32'h0000_1000`、`32'h0000_2000`、`32'h0000_3000`……同理，**4K 分界线**指低 10 bit 为 0 的地址，如 `32'h0000_0400`、`32'h0000_0800`。

AXI 系统中，**slave 地址空间一般为 4KB 的整数倍**。

**为什么不能跨越**：AXI 协议在读/写地址通道的**开头**发出 addr/len/size 等信息。若一笔 burst 跨越了 A 和 B 两个 slave，则**只有 A 收到**开头的 addr/len/size，**B 收不到**，从而造成 burst 无法完成。

## 14. AXI 的乱序访问（out of order）是什么？

当总线上有多个事务时：

- 若不同事务的 **ID 一致**，必须**顺序完成**
- 若 **ID 不一致**，则可以**乱序**

## 15. AXI 的 outstanding 是什么？

`outstanding` 指主机在**没有收到 response 时**，可以发起多个读写 transaction 的能力。

## 16. outstanding 和 interleave 有什么区别？

- **outstanding**：针对**地址**。一次 burst 还没结束，就可以发送下一个 burst 的地址，这样可以大大提高处理 transaction 的效率。
- **out-of-order** 和 **interleaving**：相对于 **transaction** 而言。
  - **out-of-order**：发送 transaction 和接收 cmd 之间的顺序没有关系。如先接到 A 的 cmd、再接到 B 的 cmd，则**可以先发 B 的 data、再发 A 的 data**。
  - **interleaving**：A 的 data 和 B 的 data 可以**交错**，如 A1 B1 A2 B2 B3……（同一个事务之间的不同数据**要按顺序**，不能出现 A1 B2 A2 B1）。

## 17. AXI3 与 AXI4 的区别？

| | AXI3 | AXI4 |
| --- | --- | --- |
| burst length 最大 | **16** | **256** |
| `WID` | **有** | **取消** |
| 写通道乱序 | 支持 out-of-order 和 interleave | **全部有序** |
| `AxQoS` | 无 | **新增**，用户服务质量信号 |

> AXI4 取消 `WID` 的目的：**避免乱序带来的死锁问题和严重的 buffer 资源浪费**。

## 18. 介绍一下 AXI 的特点？

AXI 是一种**高性能、高带宽、低延迟**的片内总线：

1. 总线的**地址/控制和数据通道是分离的**
2. 支持**非对齐**的数据传输
3. 支持**突发传输**
4. 具有**分离的读/写数据通道**
5. 支持**乱序访问**
6. 更容易进行**时序收敛**

## 19. APB 的 PSTRB 信号是什么？

**写选通信号**，指示数据总线上**哪几个字节**数据有效。

由于数据位最大为 32 bit（即 4 个字节），**`PSTRB` 位宽为 4 位**，每一位对应一个字节，置 1 时指示该字节数据有效。

> ⚠️ **读操作中，`PSTRB` 所有位必须设置为低电平**。

`PSTRB[n]` 对应 `PWDATA[(8n+7):8n]`：

```plain
 31          24 23          16 15           8 7           0
┌──────────────┬──────────────┬──────────────┬──────────────┐
│  PSTRB[3]    │  PSTRB[2]    │  PSTRB[1]    │  PSTRB[0]    │
└──────────────┴──────────────┴──────────────┴──────────────┘
   bit31:24     bit23:16      bit15:8        bit7:0
```

## 20. 如果验总线，有哪些功能点需要验？

**读写通道正确，相关信号有效。**

展开来说：地址/控制信息正确、握手信号（valid/ready）时序正确、数据正确、响应正确、burst 边界正确、outstanding 与 ID 规则正确、异常情况（back-pressure、timeout）处理正确。

## 避坑指南

- [ ] AHB 最多 4 拍（1 地址 + 3 wait），最少 2 拍
- [ ] AXI **没有独立读响应通道**，`RRESP` 搭在读数据通道里
- [ ] AXI **不允许跨 4KB 边界**；AHB **不允许跨 1KB 边界**
- [ ] outstanding 说的是**地址**层面的能力，out-of-order / interleave 说的是 **transaction** 层面
- [ ] `PSTRB` 在**读操作中必须全 0**
- [ ] AXI4 取消 `WID` 是为了**避免死锁和 buffer 浪费**
