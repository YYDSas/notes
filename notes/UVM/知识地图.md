## 一、按知识点速查

| 知识点 | 一句话 | 在哪儿 |
| --- | --- | --- |
| 九个公共相位 | build…final 是串行老链 | [[UVM · 相位与域]] |
| 两条并行时间线 | run_phase 与新链在 @0 同时开工 | [[UVM · 相位与域]] |
| function phase | build/connect…零耗时，**不能放 `#`** | [[UVM · 相位与域]] |
| 链内串行、链间并行 | 前相位占的时间原样推后同链后续 | [[UVM · 相位与域]] |
| build 自顶向下 | 父先子后 | [[UVM · 相位与域]] |
| connect 自底向上 | 子先父后 | [[UVM · 相位与域]] |
| 相位后才 create | 该组件 build/run **都不跑，且静默** | [[UVM · 相位与域]] |
| `super.<phase>()` | UVM 相位方法不是空壳，会调旧式名 | [[UVM · 相位与域]] |
| sequencer 忘 super | **default_sequence 不会启动** | [[UVM · 相位与域]] |
| objection | 每个 phase 自己的计分板，净计数 | [[UVM · 相位与域]] |
| `phase.jump()` | 域级操作；参数是相位**句柄**不是名字 | [[UVM · 相位与域]] |
| uvm_object vs uvm_component | 前者无层次，后者有 name/parent | [[UVM · 组件与工厂]] |
| `get_name` vs `get_type_name` | 实例名 vs **override 后的实际类名** | [[UVM · 组件与工厂]] |
| factory override 时机 | 必须**在 create 之前** | [[UVM · 组件与工厂]] |
| `+uvm_set_type_override` | 命令行方式，**优先级最低** | [[UVM · 组件与工厂]] |
| `run_test()` | 命令行 `+UVM_TESTNAME` **覆盖**参数 | [[UVM · 序列与 sequencer]] |
| `seq.start()` 流程 | pre_start→pre_body→body→post_body→post_start | [[UVM · 序列与 sequencer]] |
| `m_sequencer` / `p_sequencer` | 基类句柄 vs 类型化句柄（宏 cast 而来） | [[UVM · 序列与 sequencer]] |
| sequence_library RANDC | 循环随机：取遍每个 sequence 再重复 | [[UVM · 序列与 sequencer]] |
| 握手只有 4 个阻塞点 | 明面上就 `start_item` / `finish_item` / `get_response` / `get_next_item` 会卡 | [[UVM · driver 与 sequence 的握手]] |
| `get_next_item` 只 peek | 取件后队列**不变**，必须 `item_done` 才弹出 | [[UVM · driver 与 sequence 的握手]] |
| `get()` vs `get_next_item` | `get` = 取件 + **自动** `item_done`，两者**不能混用** | [[UVM · driver 与 sequence 的握手]] |
| `start_item(item)` 的 item | **必填**（无默认值）；能省的只有 priority / sequencer | [[UVM · driver 与 sequence 的握手]] |
| `output REQ` 的含义 | 阻塞 task 没有返回值 → 只能靠 `output` 带出来；`REQ` 是**类参数** | [[UVM · driver 与 sequence 的握手]] |
| 忘写 `item_done()` | 仿真**永不结束**；driver 空转同一件 item | [[UVM · driver 与 sequence 的握手]] |
| mailbox → TLM port | 把 mailbox 降级为"组件内部缓存" | [[UVM · TLM 通信]] |
| port / export / imp | 连接方向：port→export→imp，末端必须 imp | [[UVM · TLM 通信]] |
| `*_imp_decl` 宏 | 一个 checker 收多路数据时区分方法名 | [[UVM · TLM 通信]] |
| severity override | 严格是**单组件**的，不递归也不继承 | [[UVM · 报告机制]] |

| 消息 ID | 用 `get_type_name()` 按类分组（UVM 惯例） | [[UVM · 报告机制]] |

## 三、学习方法提示

- **先看现象，再看源码**：相位问题先用"两条并行时间线"讲清，别一上来就上 domain/挂载/with_phase
- **拿不准就实测**：本机 QuestaSim 自带预编译 UVM（`mtiUvm` = uvm-1.1d），
  `vlog -sv +incdir+/e/questasim/verilog_src/uvm-1.1d/src xxx.sv` → `vsim -c -L mtiUvm <top>`
- **能读源码就读源码**：`E:\questasim\verilog_src\uvm-1.1d\src\` 就在本机，这比任何二手资料都准
