## 一、30 秒默念：八股

```
tb_top                ① 顶层：时钟 + 例化 DUT + 塞 vif + run_test()
  │
  ├─ xxx_interface.sv  ② 接口：信号 + clocking + 协议 task  ← 30% 工作量在这
  │
  ├─ agents/xxx_agnt/  ③ 一个接口 = 一个 agent
  │    ├─ xxx_seq_item.sv    ④ 一个 item = 一次完整事务
  │    ├─ xxx_sequencer.sv   ⑤a 激励仲裁（AXI 这种顺序协议，空的就够）
  │    ├─ xxx_driver.sv      ⑤b 激励驱动（最简单的一个）
  │    ├─ xxx_monitor.sv     ⑥ 观测采样（最难的一个）
  │    ├─ xxx_agent_config.sv 配置对象
  │    ├─ xxx_agent.sv       ③ 装配：monitor 永远建，driver 看 is_active
  │    └─ xxx_coverage_collector.sv  ⑨ 功能覆盖率
  │
  ├─ env/               ⑦ 环境层
  │    ├─ xxx_env_config.sv   配置对象
  │    ├─ xxx_scoreboard.sv   参考模型 + 比对  ← 20% 工作量在这
  │    └─ xxx_env.sv          ③ 装配 + 连线
  │
  ├─ sequence_lib/      ⑧a 激励场景（5~15 个）
  │    ├─ xxx_base_seq.sv     公共动作 + 复位
  │    └─ xxx_xxx_seq.sv      一个功能点一个
  │
  └─ test_lib/          ⑧b 测试入口
       ├─ xxx_base_test.sv    配置面 + 封装激励入口
       └─ xxx_xxx_test.sv     一个场景一个 test
```

**三句话记死：**
1. **一个接口 = 一个 agent**，有几个接口就几个 agent
2. **一个 item = 一次完整事务**（monitor 采的、driver 驱的、scoreboard 比的都是它）
3. **一个 test = 一个激励场景 + 一组配置**（回归按 test 并行，按失败场景定位）

## 二、唯一绝对不能改的结构：三级配置链

这是 UVM 的脊柱，也是"为什么改配置不用改组件代码"的答案。

```
① tb_top          uvm_config_db#(virtual xxx_if)::set(null, "*", "IF_NAME", intf)
       ↓  接口层：唯一激励源
② base_test       env_cfg.agnt_cfg.intf = get("IF_NAME");
                  env_cfg.agnt_cfg.is_active = UVM_ACTIVE;   ← 改这里切换主动/被动
                  uvm_config_db#(env_cfg)::set(this, "*", "ENV_CFG", env_cfg);
       ↓  环境层
③ env             uvm_config_db#(agnt_cfg)::set(null, "*", "AGENT_CFG", env_cfg.agnt_cfg);
       ↓  agent 层
④ agent/driver/monitor   uvm_config_db#(agnt_cfg)::get(this, "", "AGENT_CFG");
```

**收益**：换 DUT、换角色（主动/被动）、关覆盖率、换 VIP —— 全部只改 ②，**其他文件一行不动**。

**★★ 死规矩：`super.build_phase()` 放最后一行**

```systemverilog
virtual function void build_phase(uvm_phase phase);
  env_cfg = xxx_env_config::type_id::create("env_cfg");
  env_i   = xxx_env::type_id::create("env_i", this);
  if (!uvm_config_db#(virtual xxx_if)::get(this, "", "IF_NAME", env_cfg.agnt_cfg.intf))
    `uvm_fatal("VIF_NOT_FOUND", "tb_top 没 set 虚拟接口")
  env_cfg.agnt_cfg.is_active          = UVM_ACTIVE;
  env_cfg.agnt_cfg.has_functional_cov = 1;
  env_cfg.has_scoreboard              = 1;
  uvm_config_db#(xxx_env_config)::set(this, "*", "ENV_CFG", env_cfg);
  super.build_phase(phase);      // ★★★ 必须最后
endfunction
```

放开头 → 子组件先 build → config_db 里还没有 AGENT_CFG → agent 拿不到配置就 fatal。

## 三、7 步搭建顺序（别跳步）

跳步会让调试成本翻倍。这套顺序是踩坑排出来的。

| 步 | 做什么 | 完成标志 |
| --- | --- | --- |
| 1 | `tb_defines.sv` 列 parameter 宏 | 编译过 |
| 2 | `global_pkg` + `interface` + `tb_top` 例化 DUT | 编译过 |
| **2.5** | ★ **写纯 SV 冒烟测试** | **DUT 行为全部符合预期** |
| 3 | `seq_item` + `agent_config` + `sequencer` + `monitor` | monitor 先跑通 |
| 4 | `driver` | 一个定向 seq 能跑通一次事务 |
| 5 | `scoreboard` 参考模型 | 换个非对角位宽再验一遍 |
| 6 | `base_test` + 各 seq + 各 test | 回归能跑 |
| 7 | `covergroup` bins | `vcover report` 能出分 |

### ★★ 第 2.5 步是我最想强调的

**不要直接上 UVM。** 先用 20 行纯 SV 把 DUT 跑通：

```systemverilog
initial begin
  @(posedge aresetn);
  axi_write(12'h010, 32'h1234_5678, 4'b1111);  // 写
  axi_read (12'h010);                // 读回，应该 == 12345678
  axi_read (12'hFFF);                // 越界，resp 应该是 11
  $finish;
endtask
```

**它的唯一价值是分清"RTL 错了"还是"VIP 错了"。**

> 实测：我这次的 3 个 RTL bug 全靠冒烟测试 10 分钟定位。
> 如果直接上 UVM，会误判成"VIP 写错"，在 UVM 里绕几小时。

## 六、七个"静默失败"（不报错但结果是错的）

这一组是 [[错题本 · 索引]] 里"静默失败类"在工程层面的体现。**写验证时默念一遍。**

| # | 做了什么 | 现象 |
| --- | --- | --- |
| 1 | ★★★ sequence 直接调 `intf.axi_write()` | `driven: 0 wr / 0 rd, 0 mismatches` —— **验证完全空跑，不报任何错** |
| 2 | ★★★ `recv_b` 只等 `bvalid` 不等 `bready` | 单场景全绿，串进 regress 后死等 bvalid 到看门狗 |
| 3 | ★★★ monitor 在复位期就开始采集 | 报 5 条激励里根本没发生的读（DUT 输出是 X） |
| 4 | ★★★ monitor 采样 TB 驱动侧信号走了 clocking | 12 条 `vsim-8441` + **静默采不到值**，monitor 一个 item 都不发 |
| 5 | ★★★ monitor 用 `fork...join` 汇合多个 `forever` | 编译过、仿真不报错，但永远等不到 → scoreboard 统计全 0 |
| 6 | ★★ 约束里漏 `local::` | 写 addr=0x9 读 addr=0x0，**看着像 scoreboard 的错，其实是约束写错** |
| 7 | ★★ 影子模型场景间没重置 | 16 个假 mismatch，**看着像 RTL bug，其实是模型脏了** |

**共同点：仿真都"跑完了"，不报 fatal，不中断。** 只能靠看 `SB_SUMMARY` 的数字对不对发现。

> 养成习惯：每次跑完先看这一行
> `SB_SUMMARY driven: N wr / M rd, compared K items`
> **如果 N/M 是 0，说明验证是空跑，别急着看 pass。**
