> "TB 在 posedge 驱动、监视器在同一时刻读到旧值"——这不是玄学，是可测的**竞争窗口**。
> 本篇给出时间戳级别的实测证据，以及用 `clocking` 消除它的标准做法。

## 一、timescale 必须显式写

```systemverilog
`timescale 1ns/1ps
```

- 编译 interface / module 时若不写，vsim 报 `vsim-3009 [TSCALE]` 并 **Error loading design**
- 格式是 `单位/精度`：`1ns/1ps` 表示时间单位 1ns、精度 1ps
- 注意 Questa 控制台里 `%t` 按**精度**渲染：`1ns/1ps` 下 1ns 打印成 `@1000`

## 二、驱动/采样的基本时序纪律

> **数据在 `negedge` 改，采样在 `posedge` 等。**

这么做是为了让驱动和采样**天然错开半个周期**，避免同一时刻读写冲突。
如果 TB 和监视器都在 `posedge` 动作，就会落进下面的竞争窗口。

## 三、竞争窗口是什么（时间戳实测）

不用 clocking 时（`ts_sim` 里的 `race_timing.sv`），实测日志：

```
[25000] posedge | plain_if.sig = 0      ← 监视器读到「旧值 0」
[25000] TB (plain) : drove sig=1        ← TB 在「同一时刻」写入 1
```

**同一个时刻 25000**，一边读到 0、一边写 1 —— 谁先谁后由调度决定，标准**不保证顺序**。
这就是经典的 race condition。

## 四、用 clocking block 消除竞争

```systemverilog
interface chnl_intf(input clk);
  logic sig;

  clocking drv_ck @(posedge clk);
    default input #1ns output #1ns;
    output sig;               // 驱动侧
  endclocking

  clocking mon_ck @(posedge clk);
    default input #1ns;
    input sig;                // 采样侧
  endclocking
endinterface
```

- `output #1ns`：驱动**推迟**到采样点之后 1ns 生效
- `input #1ns`：采样取的是**1ns 之前的稳定值**
- 实测：改用 `output #1ns` 后，驱动落到 posedge+1ns，**无人竞争**

## 五、⚠️ 竞争没出错 ≠ 没有竞争

一个诚实的负面结果：`clk_demo.sv` 里用与不用 clocking，`sum` 都是 60 ——
**这次竞争没有导致错误结果**（Questa 在 `-O0/-O3/-O5` 下调度一致）。

> 正确的教学口径：**"竞争没出错"不等于"没有竞争"**。
> SV 标准不保证顺序，`clocking` 的价值是**从结构上确定顺序，而不是依赖运气**。
> 换工具、换版本、换优化级别，结果都可能翻车。

## 六、driver / monitor 里怎么用

```systemverilog
class chnl_driver;
  virtual chnl_intf vif;
  task do_drive();
    @(vif.drv_ck);            // 等驱动时钟块
    vif.drv_ck.sig <= data;   // 通过时钟块驱动
  endtask
endclass

class chnl_monitor;
  virtual chnl_intf vif;
  task do_mon();
    @(vif.mon_ck);            // 等监视时钟块
    data = vif.mon_ck.sig;    // 通过时钟块采样
  endtask
endclass
```

> 时钟块把"什么时候驱动、什么时候采样"从**运行期运气**变成**接口里的规格**——
> 这也是 UVM 里 interface 内建 `drv_ck` / `mon_ck` 的原因。
