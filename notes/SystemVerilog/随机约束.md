> 随机化是验证的核心生产力，也是"静默失败"的重灾区。
> 本篇所有结论都在本机 QuestaSim 10.7c 实测过；⚠️ 标记的是踩过的坑。

## 一、rand / randc 与 randomize()

```systemverilog
class packet;
  rand  bit [7:0] id;     // 每次随机独立
  randc bit [1:0] ch;     // 循环随机：取遍所有值前不重复
endclass
```

- `rand`：均匀取值（受约束裁剪）
- `randc`：**循环**取值，一轮内不重复，适合"通道轮流"这类场景
- 只有 `rand`/`randc` 变量会被 `randomize()` 处理

## 二、new() 不随机化

```systemverilog
packet p = new();
// 实测：所有 rand 变量 = 0（数值默认值），不是随机值
```

**`new()` 只做初始化（声明处的初值 + 构造体赋值），不做随机**。
看到"打印全 0"别以为随机没生效——是还没调用 `randomize()`。

## 三、constraint 约束块 与 inline with

```systemverilog
class packet;
  rand int len;
  constraint c_short { len inside {[1:32]}; }     // 类内约束
  constraint c_long  { len inside {[1000:1023]}; }
endclass

p.randomize();                        // 用类内约束
p.randomize() with { len == 500; };   // inline 约束：与类内约束同时生效
```

**关键**：inline 约束与类内约束是"**求交**"，两边都要满足。

**⚠️ 互斥约束 = randomize() 返回 0（报错）**
`c_short`（1~32）与 `c_long`（1000~1023）交集为空 → solver 失败 →
`assert(p.randomize())` 失败。考试题里"不禁止任何约束块时 length 可能是？"，正确答案是"**报错**"。

## 四、soft：可被覆盖的"软约束"

```systemverilog
constraint c_soft { soft ch_id == 1; }
```

| 场景 | randomize() | 结果 |
| --- | --- | --- |
| `soft ch_id==1` + inline `ch_id==2` | 1 | **ch_id=2**（inline 覆盖 soft） |
| 只有 `soft ch_id==1` | 1 | ch_id=1 |
| `ch_id==1`（硬） + inline `ch_id==2` | **0** | 冲突失败 |

> `soft` 的语义 = "**没有更高优先级要求时，我希望这样**"。
> 这正是 UVM sequence 里 default constraint 用 soft 的原因：基类给出默认偏好，子类/test 可以无痛改写。

## 五、dist 是"期望比例"，不是精确配额

```systemverilog
constraint c { val dist { 1 := 1, 2 := 2, 3 := 5 }; }   // 权重 :=
```

实测：权重 1:2:5 跑 **4000 次**，得到 **126 : 245 : 628**（每千次期望 125:250:625）。

- 有统计波动 → **覆盖率不可能一次跑满**
- 这也解释了 MCDF `full_random_test` 覆盖率只有 41.9%：随机跑得少，bin 自然填不满

## 六、⚠️ `inside {3,5}` 与 `inside {[3:5]}` 的区别

| 写法 | 含义 | 成员 |
| --- | --- | --- |
| `{3,5}` | **枚举集合**（value set） | 只有 3 和 5 |
| `{[3:5]}` | **区间**（range） | 3、4、5 |

题目：类内 `da.size() inside {[3:5]}`（区间），inline `da.size() inside {3,5}`（集合），
两者**求交** → 最终 `size ∈ {3, 5}`，**长度 4 不可能**。

> **别把 `{3,5}` 口头读成"3 到 5"**。看到 `inside` 先逐字符确认是花括号枚举还是方括号区间。

**联动**：`foreach(da[i]) da[i] < da[i+1];` 展开的条数 = `size()-1`，**由随机结果反推**，不是固定的。
size=3 时 2 条比较，size=5 时 4 条。

## 七、⚠️ solve ... before 只能写变量名

```systemverilog
solve payload.size() before x;    // ❌ (vlog-13022) near ")": syntax error
```

`solve ... before ...;` **只能写变量名，不能写表达式**。正确做法是加辅助变量：

```systemverilog
rand int pkt_len;
constraint c {
  solve pkt_len before fsm_state;   // ✅ 变量名
  payload.size() == pkt_len;
}
```

## 八、⚠️ 动态数组不约束 size = 静默失败

```systemverilog
rand bit [7:0] payload[];
constraint c { payload.size() inside {[4:64]}; }   // ← 必须显式约束 size
```

实测：**不约束 size 时 `randomize()` 返回 1（成功！）但 `size = 0`**，
无 error、无 warning。`cg.sample()` 调 0 次，功能覆盖率 0%。

**两条必记**：

1. 动态数组的 `size` 必须显式约束
2. 约束了 `size` ≠ 约束了元素，逐元素要用 `foreach(payload[i])`

## 九、randomize() 失败后，rand 变量到底变不变？

**实测结论（用哨兵值验证）：失败时变量"保持原值不变"，不会清零。**

| 场景 | 失败后 |
| --- | --- |
| 类内互斥约束（先置 `length=777` 哨兵） | 仍是 777 |
| 类内硬约束 + 冲突 inline（先成功随一次） | 保持上次成功值 |

> **为什么很多人记成"清零"**：对象 `new()` 后 rand 变量本来就是 0，用 0 无法区分"清零"和"保持"。
> 测这个问题**必须先用哨兵值或先成功随一次**。
> LRM 未强制规定失败后的取值（实现相关），所以结论是：**绝不能依赖失败后的值，必须判断 `randomize()` 的返回值。**

## 十、⚠️ constraint_mode()：逐块开关 vs 对象级

```systemverilog
p.c_short.constraint_mode(0);   // 关掉 c_short 这一块（语句形式）
p.constraint_mode(0);           // 关掉该对象所有约束块
```

| 坑 | 说明 |
| --- | --- |
| **返回值不能接** | Questa 10.7c 把它按 `void` 声明：`r = p.constraint_mode(0);` → `Function with return type of void cannot be used in/as an expression`。**只能当语句用**，要记状态自己用 `bit` 变量存 |
| **对象级会"无差别全开"** | `p.constraint_mode(1)` 会把该对象**所有**约束块打开，**覆盖**之前逐块 `constraint_mode(0)` 的关闭状态（实测：两块都关→随机成功；再对象级开→立刻冲突失败） |

## 十一、randomize(实参) 的特殊语义

```systemverilog
r.randomize(low);    // 只随机化 low，其余 rand 变量降级为常量参与求解
```

自查清单（依据 LRM §18.6.1、§18.11）：

1. 只有**实参列表里的变量**被随机化，其余 `rand` 变量当作 state variable（常量）参与求解
2. 实参**不必是 `rand` 变量**——传进去就临时获得被随机化的资格（`low` 虽非 rand 也会被随机化）
3. 实参只能是"被随机化对象的**属性名**"，**不能是表达式或层次路径**（如 `randomize(obj.a1)` 非法）
4. 全部活动约束依旧生效、**必须同时满足**，否则整次调用返回 0
   —— 这才是 `r.randomize(low)` 在 `med=hi=0` 时报错的真正原因（约束 `med < hi` 即 `0 < 0` 恒假）
5. `randomize(null)` = 不随机化任何变量，只检查约束是否成立（当"约束检查器"用）

## 十二、assert(randomize()) 的报错形态

```systemverilog
assert (p.randomize());                 // 失败：打印 ** Error: Assertion error. + Time/Scope/File/Line，仿真继续
assert (p.randomize()) else $error("randomize failed");   // 只走 else 分支，不再额外打 assertion 消息
```
