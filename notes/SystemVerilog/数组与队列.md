> 四种"数组"长得像，用法差很远。本篇把**要不要 new、怎么扩容、存的是值还是句柄**一次讲清。

## 一、四种数组一览

| 类型 | 声明 | 初始大小 | 要不要 new | 常见操作 |
| --- | --- | --- | --- | --- |
| 定长数组 | `byte a[4];` | 4 | 不要 | `$size()`、`foreach` |
| 动态数组 | `byte a[];` | **0** | **要** `a = new[n];` | `size()`、`delete()` |
| 队列 | `byte q[$];` | 0 但**可用** | 不要 | `push_back` / `pop_front` / `size()` |
| 关联数组 | `byte m[string];` | 0 | 不要 | `exists()` / `delete()` |

> **队列 `[$]` 声明即创建**——是一个"空但可用"的容器，直接 `push_back` 就行。
> **动态数组 `[]` 声明后什么都没有**，必须 `new[n]` 才有元素。这是最高频的混淆点。

## 二、动态数组必须 new[n]

```systemverilog
byte nb[];
nb[0] = 8'hAA;      // 💥 越界（size 仍为 0）
nb = new[8];        // ✅ 才有 8 个元素
```

**最危险的形态**：句柄数组没分配就赋值。

```systemverilog
packet pkts[];                 // size = 0
pkts[0] = eth1;                // 静默丢弃
pkts[1] = ctrl1;               // 静默丢弃
foreach (pkts[i]) ...          // 跑 0 次 → 什么都没验证
```

实测：`pkts.size()` 前后都是 0，**0 错 0 警**，整段多态演示零输出——"验证环境通过了但什么都没验证"。

## 三、句柄数组：`new[5]` 是 5 个空槽

```systemverilog
packet ps[] = new[5];   // 5 个元素，每个都是 null 句柄（不创建对象）
```

- `new[n]` **只分配"句柄槽"**，槽里是 `null`，不会替每个元素调构造函数
- 要真正有对象，还得逐个 `ps[i] = new();`
- 同理：**声明句柄数组不产生对象，`new()` 执行几次才有几个对象**

### 扩容：`new[8](ps)`

```systemverilog
ps = new[8](ps);   // 扩到 8 个，前 5 个复制旧内容，新增 3 个为 null
```

带括号的第二个参数是**源数组**，语义是"新建更大的、把老的拷进来"。
不带源参数 `new[8]` 则是全新分配，**老元素全部丢失**。

## 四、动态数组拼接：`buffer = {buffer, data}`

要把两块动态数组接起来，最常用的写法：

```systemverilog
byte buffer[] = new[4];
byte data[]   = new[2];
...
buffer = {buffer, data};   // 重新分配并拼接：长度 = 6
```

- `{a, b}` 生成一个**新的临时数组**，再赋回 `buffer`
- 拼接方向：**左边的在前**（低索引）
- 因为右侧长度会变，所以这是"重新分配"，不是原地追加
- 频繁拼接大数组时性能差，循环里慎用

## 五、push_back 存的是句柄，不是快照

```systemverilog
t = new();                     // 全程只 new 一次
for (int i = 0; i < 3; i++) begin
  t.addr = i << 2;
  fifo.push_back(t);           // 压入同一个句柄
end
// fifo[0] / fifo[1] / fifo[2] 全是 8 —— 同一个对象的最新值
```

要保存多个不同状态，**必须每次 new 新对象**：

```systemverilog
for (int i = 0; i < 3; i++) begin
  t = new();                   // ← new 挪进循环
  t.addr = i << 2;
  fifo.push_back(t);
end
```

> **句柄数组 / 队列里存的是"门牌号"**，不是对象内容的照片。对象改了，数组里看到的就是新值。

## 六、元素个数写法：`comp[2]` vs `comp[0:2]`（实测）

```systemverilog
packet comp  [2];      // 单个数字 = 元素【个数】→ 2 个元素，下标 0、1
packet comp2 [0:2];    // 范围写法 = 下标【范围】→ 3 个元素，下标 0、1、2
```

| 写法 | `$size()` | 合法下标 |
| --- | --- | --- |
| `comp[2]` | 2 | 0、1 |
| `comp[0:2]` | 3 | 0、1、2 |

（实测脚本 `ts_sim/array_size_demo.sv`。）

> 顺带一个 Questa 行为：固定尺寸非打包数组的**常量越界访问不报错**（声明 `comp[2]` 却访问 `comp[2]`：编译 0 错 0 警、运行静默通过）。
> off-by-one 不会自己暴露 —— 写遍历一律用 `foreach`，或先 `$size()` 自保。
