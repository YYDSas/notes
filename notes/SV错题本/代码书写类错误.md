> 这一类错误的共同点：**编译器能抓出来**，属于"手滑/疏忽"，不涉及概念。
> 特点是重复率高、修起来快，但每次都浪费编译轮次。建议对照文末清单逐项自查。

## 一、分号类（最高频）

### 1.1 函数/任务头漏分号

```systemverilog
// ❌ 函数头这一行末尾必须有分号
function new(string name = "packet_base")
  this.name = name;
endfunction
```

编译器反应：

```
** Error: (vlog-13069) near "this": syntax error,
          unexpected "SystemVerilog keyword 'this'", expecting ';'.
```

**要点**：`function` / `task` 的**头部（含参数列表）必须以 `;` 结束**，然后才是函数体。

### 1.2 调用语句漏分号

```systemverilog
function new();
  super.new("packet_eth")     // ❌ 漏分号
  length = 64;
endfunction
```

### 1.3 一行多个语句时只写了第一个分号

```systemverilog
int a, b, c    // ❌
int a, b, c;   // ✅
```

## 二、拼写类

| 写错 | 正确 | 编译器报错 |
| --- | --- | --- |
| `naem` | `name` | 形参名错，不报错但逻辑错 |
| `forecah` | `foreach` | `syntax error, unexpected begin` |
| `packet_crtl` | `packet_ctrl` | `(vlog-2730) Undefined variable: 'crtl'` |

**最难发现的拼写错误**：形参名拼错。编译器不报错，因为 `naem` 是个合法标识符，只是你后面没用它。

```systemverilog
// ❌ 形参叫 naem，函数体却用 name（成员自己）→ 自己给自己赋值
function new(string naem = "packet_base");
  this.name = name;        // name 是成员，等于 this.name = this.name
endfunction
```

**防御**：形参故意用**不同名字**（如 `name_i` / `n`），或者写函数体时**回头看一眼形参名**。

### 2.1 非 ASCII 字符：肉眼最难发现的一类

中文输入法 / 复制粘贴会带进来两种字符，**看起来和正确写法几乎一样**，但编译器一定报错：

| 陷阱 | 长什么样 | 正确写法 | 后果 |
| --- | --- | --- | --- |
| **全角分号** `；` | `#10；` | `#10;` | 语法错误 |
| **反引号当单引号** | ``void`($cast(rsp,req.clone()));`` | `void'($cast(...));` | `` ` `` 被当作宏起始，报宏名非法 |

> **防御**：写完全局搜一遍 **`；`** 和 **`` ` ``**。
> 反引号只应出现在宏名前面（如 `` `uvm_error ``、`` `uvm_component_utils ``），别的地方出现都是错的。

### 2.2 手写 UVM 环境时的高频错单（真实作业实录）

这一类错集中在"字母顺序"和"形近词"上 —— **编译器能抓，但一条报错往往带出十几条连锁**，
容易被淹没在错误列表里。

| 写错 | 正确 | 备注 |
| --- | --- | --- |
| `` `tmiescale `` | `` `timescale `` | 编译指令名拼错 |
| `nidlesinside {[0:3]}` | `nidles inside {[0:3]}` | **关键字前漏空格**，被当成一个标识符 |
| `$tmie` | `$time` | 系统函数名 |
| `finsih_item` | `finish_item` | 字母顺序颠倒 |
| `seq_itme_port` / `seq_time_port` | `seq_item_port` | **`uvm_driver` 的内建端口名，写错频率最高** |
| `sqr` ↔ `srq` | 统一成一个名字 | 成员名与使用处**对调**，最难自查 |
| `` `uvm_component_utils(driver) `` | `` `uvm_component_utils(my_driver) `` | 宏参数必须是**真实类名** |
| `` `include "uvm.macros.svh" `` | `` `include "uvm_macros.svh" `` | 文件名多一个点 → 头文件找不到 |
| `run_phase(uvm_phase phase);` | `virtual task run_phase(uvm_phase phase);` | 类里声明方法**必须带 `function` / `task`** |

**最有效的防御**：写完只读**名字**、不读逻辑 —— 从头到尾把每个标识符逐字念一遍。
上面这些错，念一遍全都能抓出来。

## 三、`this.` 与同名遮蔽

```systemverilog
// ❌ 形参名与成员同名时不加 this.，赋值方向搞反或自赋值
function new(string name);
  name = name;             // 形参 = 形参，成员没被赋值
endfunction

// ✅ 必须用 this. 明确指出是成员
function new(string name);
  this.name = name;        // this.name 是成员 ← 右边的 name 是形参
endfunction
```

**记忆**：`this.成员 = 形参`。左边是成员，右边是形参。

## 四、声明位置

```systemverilog
initial begin
  $display("start");          // ← 语句
  packet_base pkts[];         // ❌ 声明写在语句之后
end
```

编译器反应：

```
** Error: Illegal declaration after the statement near line '46'.
          Declarations must precede statements.
```

**规则**：`begin...end` 块里，**所有声明必须放在所有语句之前**（和 C 的老标准一样）。

## 五、有返回值却不 `return`

```systemverilog
// ❌ 声明返回 int，函数体却只 $display
function int get_length();
  $display("length is %0d", length);
endfunction
```

**实测结果（QuestaSim 10.7c）**：

```
inside: length=64
get_length() returned = 0     ← 静默返回 0，而且【连 warning 都没有】！
```

**这是最阴的错误**：编译无警告，运行不报错，就是值不对。调用方拿到 0 还以为是对的。

**要点**：取值函数就 `return`，别在里面 `$display`。"取值"和"打印"是两个职责。

## 六、动态数组忘记分配

```systemverilog
packet_base pkts[];      // 声明了，但没有分配
pkts[0] = eth1;          // 💥 越界/未初始化
```

**必须显式分配**：

```systemverilog
pkts = new[3];           // ✅ 分配 3 个元素
```

> 对比：队列 `pkts[$]` **不需要** new，声明即可用。

## 七、`$display` 格式串不匹配

```systemverilog
$display("CRTL:opcode=");                 // ❌ 没有格式符，也没给值
$display("CTRL: opcode=%0d", opcode);     // ✅
```

常见变体：
- 有 `%d` 却没给参数 → 打印出垃圾值
- 给了参数却没有格式符 → 参数被忽略
- 用 `%d` 打印 `bit[47:0]` 的多位值 → 该用 `%h` 或 `%0d`

## 八、类名 / 变量名混用

```systemverilog
class packet_ctrl extends packet_base;   // 类名：packet_ctrl
...
packet_crtl crtl;                        // ❌ 类型名写成 packet_crtl
```

**建议**：类名统一用 `packet_ctrl`，变量名用 `ctrl`（去掉 `t` 前面的字母，别和类名太像）。名字太像时，改名字不如**改命名习惯**。

## 九、覆盖率代码的高频错（covergroup 专属）

写 `covergroup` 时的错误很集中，一次踩全了：

```systemverilog
// ❌ 1. covergroup 体里写变量声明 / 语句
covergroup cg_pkt;
  cp_len: coverpoint s { bins ... }
  int s = payload.size();            // ❌ 体里只能放 coverpoint / cross / 选项
endgroup
// ✅ 先在 sample 之前把值算好存进成员变量，coverpoint 只看"本作用域能看到的变量"

// ❌ 2. coverpoint 引用了不属于本类的字段
cp_pkt: coverpoint pkt_type;         // ❌ pkt_type 是 packet 类的字段，这里看不到
// ✅ 本类加 bit[15:0] s_type;，在 sample_pkt(p) 里 this.s_type = p.pkt_type;

// ❌ 3. 全角冒号（中文输入法）
cp_gap ：coverpoint gap { ... }      // ❌ "：" 不是 ASCII 冒号
// ✅ cp_gap: coverpoint gap { ... }

// ❌ 4. 区间漏了方括号
bins gap_mid = {1:3};                // ❌ 这不是区间
// ✅ bins gap_mid = {[1:3]};        // {[1:3]} 区间 / {1,3} 两个点 / {1:3} 非法

// ❌ 5. 构造函数写进了别的函数里
function void sample_pkt(...);
  ...
  function new(); endfunction        // ❌ new() 不能嵌套在函数/任务内部
endfunction

// ❌ 6. randomize 裸调用 + 用 = 而不是 ==
randomize() with { pkt_type = TYPE_IP, payload.size inside {4:7} };
// ✅ p.randomize() with { pkt_type == TYPE_IP; payload.size() inside {[4:7]}; }
```

| 错误 | 后果 | 记法 |
| --- | --- | --- |
| covergroup 里写变量/语句 | 编译不过 | 体里**只放 coverpoint / cross / 选项** |
| coverpoint 引用别类的字段 | 编译不过（`Undefined variable`） | **"本作用域能看到的变量"**才可覆盖 |
| 全角 `：`、`（`、`，` | 编译不过，报错位置常看着没问题 | 出错先查**中英文标点** |
| `{1:3}` 少了 `[ ]` | 语义完全变了（或直接报错） | **区间 = `{[a:b]}`，集合 = `{a,b}`** |
| `new()` 嵌在 function 里 | 编译不过 | `new()` 只能属于**类** |
| `covergroup` 忘 `new()` / 忘 `sample()` | **覆盖率恒 0，且不报错** | 两个"必须"缺一不可 |
| `option.weight` vs `type_option.weight` | 前者是 covergroup 的选项，后者是 coverpoint/cross 项的选项 | 想"只统计不拉分"用 `type_option.weight = 0` |

> `covergroup` 忘 `new()` 和忘 `sample()` 属于**静默失败**：0% 和"真没覆盖到"在报告里长得一样，
> 所以看到某个 covergroup 全 0，**第一件事是先确认它到底有没有被采样**。详见 [[SV · 功能覆盖率]]。

## 十、UVM 代码的"框架级"书写错（默写 UVM 环境时集中踩）

### 10.1 骨架不配对（最致命）

```systemverilog
class my_com extends uvm_component;
  ...
  endfunction               // ← 只配了 endfunction
                            //   ？？？ 没有 endclass
class my_test extends uvm_test;      // ← 编译器把 my_test 当成 my_com 的【嵌套类】
```

后果：报错位置看着莫名其妙，后面一大串全在报错，实际只有一个 `endclass` 没写。

**五对括号，写完立刻配对**：

| 开 | 关 |
| --- | --- |
| `package` | `endpackage` |
| `class` / `covergroup` | `endclass` / `endgroup` |
| `module` / `interface` | `endmodule` / `endinterface` |
| `function` / `task` | `endfunction` / `endtask` |
| `begin` / `fork` | `end` / `join` |

> 默写时的正确姿势：**先把骨架搭出来**（package/endpackage、class/endclass、module/endmodule 全部配好），再往里填内容。

### 10.2 类型名拼错 / 同名函数写两遍

```systemverilog
function void build_phase(uvm phase);         // ❌ 少了 _
function void build_phase(uvm_phase phase);   // ✅
```

```systemverilog
// ❌ 同一个 build_phase 写了两遍
function void build_phase(uvm_phase phase); super.build_phase(phase); endfunction
function void build_phase(uvm_phase phase); uvm_config_db#(int)::get(...); endfunction
```

**SV 不支持函数重载**：同类中同名函数出现两次就是**重复定义**，直接报错（哪怕参数不同）。

### 10.3 factory 创建写成了"作用域解析"的样子

```systemverilog
my_com::creat::type_id::("my_com", this);          // ❌ 完全不是这个语法
m_comp = my_comp::type_id::create("m_comp", this); // ✅
```

**✅ 三层记法**：`类名 :: type_id :: create("实例名", parent)`

- `type_id` —— `` `uvm_component_utils `` 宏生成的**类型代理**（类里的一个 typedef）
- `create` —— 它的**静态方法**（走 factory，不是 `new`）
- 第一个参数是**实例名**（决定层次路径），第二个是 parent

### 10.4 `run_test` 少写了 `_test`

```systemverilog
run("my_test");           // ❌ 没有这个函数
run_test("my_test");      // ✅
```

### 10.5 `` `uvm_info `` 的参数个数（三个！）

```systemverilog
`uvm_info("my_com", UVM_LOW);                 // ❌ 第二个参数位置塞了 verbosity，MSG 丢了
`uvm_info("BUILD", "cfg_val = 42", UVM_LOW)   // ✅ ID, MSG, VERBOSITY
```

> ⚠️ 少参数时编译器报的是**宏实参个数**问题，不会提示"你少了消息字符串"，容易看晕。
> 另外：MSG 里不要写死字符串 —— 要带上变量值，见 [[错题本 · 静默失败类]]。

### 10.6 `begin` 没配 `end`；objection 当成独立函数

```systemverilog
function void report_phase(uvm_phase phase);
  if (x) begin
    `uvm_info("RPT", "…", UVM_LOW)
endfunction                   // ❌ begin 的 end 呢？
```

```systemverilog
raise_objection(this);             // ❌ 没有全局的 raise_objection
phase.raise_objection(this);       // ✅ objection 是【phase 对象的方法】
phase.drop_objection(this);        // ✅ 与 raise 配对出现
```

### 10.7 把类型名当变量 / 声明了没用的成员

```systemverilog
my_test c2;                                            // 声明了从没用过
uvm_config_db#(int)::get(this, "", "my_com", my_com);  // ❌ 第 4 个实参是【类名】
uvm_config_db#(int)::get(this, "", "cfg_val", cfg_val);// ✅ 必须是同类型的【变量】
```

### 10.8 对 coverpoint 的名字赋值

```systemverilog
this.cp_len = p.cp_len;              // ❌ 左边是 coverpoint 的名字（不是变量），右边也不存在
this.s_len  = p.payload.size();      // ✅ 类成员 ← 对象字段
```

### 报错关键词速查

| 编译报错 | 你大概率写了 |
| --- | --- |
| `syntax error … expecting ';'`（在下一个 `function`/`ignore_bins` 处） | 上一条语句/宏/声明漏了 `;` |
| 一连串报错都指向同一个类后面 | **`endclass` / `endgroup` / `endmodule` 漏了** |
| `Undefined variable: 'xxx'` | 拼写不一致，或引用了**别的作用域**的名字 |
| `Too few arguments`（宏/函数） | `` `uvm_info `` 少参数、`get` 少参数 |
| `Illegal use of a type name as an expression` | 把**类名**当变量传给了函数 |
| `Illegal declaration after the statement` | 声明写在了语句之后 |

## 十一、跑不起来但代码"看着没错"（工程/运行配置类）

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| `Error loading design` / 找不到顶层 | **模块名 ≠ 命令里的顶层名**（文件名、模块名、`vsim` 后面的名字三处要一致） | 三处对齐；一个字母顺序错了也算 |
| `#5` 的时间不对 | 源文件没有 `` `timescale `` | 每个文件开头写 `` `timescale 1ns/1ps `` |
| UVM 编译/运行报找不到 | 编译缺 `+incdir+<uvm>/src`，或运行缺 `-L mtiUvm` | 见 [[仿真工具 · Questa 命令行与 Makefile]] |
| 覆盖率 `.ucdb` 没生成 | `coverage save -onexit` 写在了 `run` 之后（被 `$finish` 吃掉） | **写在 `run` 之前** |

## ✅ 提交前自查清单（按出错频次排序）

- [ ] 每个 `function` / `task` **头部行**末尾有 `;` ？
- [ ] 每个函数调用、每条赋值末尾有 `;` ？
- [ ] 形参名与成员同名时，成员侧写了 `this.` ？
- [ ] 拼写：`foreach` / `name` / 类名一致 ？
- [ ] `begin...end` 里声明是否都在语句之前 ？
- [ ] 声明返回值的函数，**每条执行路径**都有 `return` ？
- [ ] 动态数组 `[]` 是否 `new[n]` 了 ？（队列 `[$]` 不用）
- [ ] `$display` 的格式符个数与参数个数**是否相等** ？
- [ ] 有返回值函数的调用，是否真的用了返回值（`void'()` 或接收）？
- [ ] `covergroup` 体里只放了 coverpoint / cross / 选项（没有变量声明）？
- [ ] `covergroup` 是否 `new()` 了？`sample()` 是否真的被调用了？
- [ ] `{...}` 里的区间都带 `[ ]` 了吗（`{[1:3]}`）？冒号是 **ASCII** 的吗？
- [ ] **五对括号**都配对了吗：`package` / `class` / `covergroup` / `module` / `begin` ？
- [ ] 同一个类里有没有**同名函数写两遍**（SV 不支持重载）？
- [ ] `类名::type_id::create("实例名", parent)` 三层写全了吗（`creat` 别拼错）？
- [ ] `` `uvm_info `` 的**三个**参数（ID, MSG, VERBOSITY）都在吗？MSG 里带变量值了吗？
- [ ] `phase.raise_objection(this)` 与 `phase.drop_objection(this)` 配对了吗？
- [ ] **文件名 / 模块名 / `vsim` 顶层名** 三处一致吗？
- [ ] 每个源文件开头都有 `` `timescale `` 吗？
