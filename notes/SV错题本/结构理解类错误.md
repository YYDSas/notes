> 这一类错误的共同点：**编译器抓不出来**，代码长得没毛病、可能还能跑，
> 但语义理解偏了，结果是"看着对、其实错"。只能靠脑内模型修正。

## 一、把 `super` 当成句柄

**错误理解**："`super.clone(ct)` 是调用父类的克隆函数，把 ct 作为参数传进去，`super` 就像一个指向父类的句柄。"

**正确理解**：`super` 是**「父类版本的方法」**，跟任何句柄无关。

```systemverilog
class chnl_trans extends trans;
  virtual function trans clone(trans t = null);
    chnl_trans ct;
    if (t == null) ct = new();
    void'(super.clone(ct));   // ← 调用【父类 trans 里的 clone】，形参 t = ct
    ct.ch_id = ch_id;
    return ct;
  endfunction
endclass
```

拆解：
- `super` = 指名调父类实现（**静态绑定**，不受多态影响）
- `(ct)` = 把子类局部变量 ct 作为参数传给父类方法

**判断口诀**：`super.X()` 读作「调用**父类版本的** X 方法」，不要读成「父类句柄调 X」。

## 二、`$cast` 的作用不明

**错误想象**：`$cast` 会创建对象、或者转换数据、或者"把父类对象变成子类对象"。

**正确理解**：`$cast` 做且只做两件事：

1. **运行时类型检查**——检查源句柄指向的对象，其实际类型能否赋值给目标类型
2. **给同一个对象再加一个句柄**——成功则目标句柄也指向那个对象

**它不创建对象、不复制数据、不改变对象的类型。**

```
对象①（实际类型 chnl_trans）
   ↑              ↑
   t2            ct2        ← 两个句柄，一个对象
（trans 类型）  （chnl_trans 类型）
   ↑ $cast 只是加了右边这个句柄，并检查了类型
```

**为什么需要它**：句柄的静态类型决定你能访问哪些成员。`t2.ch_id` 编译报错（trans 没有 ch_id），`ct2.ch_id` 才行。

> **补充**：给 `ch_id` 加 `virtual` **也没用**。`virtual` 只能修饰**方法**，不能修饰数据成员。数据成员不存在多态。

## 三、子类构造函数忘记 `super.new()`

```systemverilog
// ❌ 没有调 super.new()，父类的 name 根本没被初始化
class packet_ctrl extends packet_base;
  function new();
    name = this.name;        // 无意义的自赋值
  endfunction
endclass

// ✅
class packet_ctrl extends packet_base;
  function new();
    super.new("packet_ctrl");   // 先把父类部分初始化好
    length = 8;
    opcode = 4'h5;
  endfunction
endclass
```

**要点**：子类构造函数**必须先 `super.new(...)`**，把父类那部分成员初始化掉，再初始化自己的成员。
忘了调，父类成员就是默认值（`string` 是空串、`int` 是 0），后面打印出来是空的。

## 四、方法的职责边界不清楚

```systemverilog
// ❌ 在 show() 里改数据
virtual function void show();
  length = 8;                    // show 不该改数据！
  $display("CTRL: opcode=%0d", opcode);
  super.show();
endfunction
```

**`show()` 只负责"显示"，构造/配置只负责"设置"**。混在一起会有两个后果：
1. 调一次 `show()` 数据就被改一次，**不幂等**
2. 想看当前值却把值改掉了，调试时会被自己骗

**心里给每个函数贴标签**：取值函数 / 显示函数 / 设置函数 / 计算函数 —— 一个函数**只干一件事**。

## 五、对象个数的判断

**错误直觉**：以为 `t2 = t1` 会"复制出一个新对象"。

**正确判断**：**只有 `new()` 才产生新对象**。数一数代码里 `new()` 执行了几次，就有几个对象。

```systemverilog
t1 = new();          // new #1 → 对象①，obj_id = 1
t2 = t1;             // 没有 new！t2 和 t1 指向同一个对象①
t3 = t1.clone();     // clone 内部有 new → 对象②，obj_id = 2
```

实测输出：

```
t1 object ID is [1]
t2 object ID is [1]    ← 与 t1 同一个对象
t3 object ID is [2]    ← clone 出的新对象
```

| 写法 | 产生新对象？ |
| --- | --- |
| `t2 = t1;` | ❌ 否，句柄复制 |
| `t3 = t1.clone();` | ✅ 是（clone 内部调了 new） |
| `t4 = new();` | ✅ 是 |

## 六、以为 `fifo[$]` 需要实例化

**错误疑问**："`fifo[$]` 没有实例化，传进去的 t 去哪了？"

**正确理解**：

| 类型 | 声明 | 要不要 new |
| --- | --- | --- |
| 队列 `Transaction fifo[$];` | 声明即创建 | **不要**，直接可用 |
| 动态数组 `byte nb[];` | 声明后未初始化 | **要**：`nb = new[n];` |

队列声明的那一刻就是"空但可用"的状态，可以立刻 `push_back` / `size()` / `pop_front`。

## 七、以为 `push_back` 存的是"快照"

**错误直觉**：`fifo.push_back(t)` 像是把 `t` 当前的值**复制一份**存进去。

**正确理解**：存的是**句柄**（门牌号），不是对象、也不是快照。

```systemverilog
t = new();                       // 全程只 new 一次
for (int i = 0; i < 3; i++) begin
  t.addr = i << 2;               // 反复改同一个对象
  fifo.push_back(t);             // 三次压入同一个句柄
end
// 实测：fifo[0]、fifo[1]、fifo[2] 全是 8
```

**类比**：通讯录里抄的是**电话号码**，不是把那个人搬进通讯录。人搬家（对象内容变）了，
通讯录里还是同一个号码，打过去还是那个人。

**要存多个不同状态 → 必须每次 `new` 新对象**。

## 八、`virtual` 的作用范围

**错误直觉**：以为"子类重写时必须写 `virtual`，不写就失效"。

**实测结论（两组对照仿真）**：

| 实验 | 结果 |
| --- | --- |
| 基类有 `virtual`，子类去掉 `virtual` | **输出完全不变**（虚性会自动继承） |
| 基类去掉 `virtual`，子类有 `virtual` | **多态失效**，只剩父类方法被调用 |

```
// 基类去 virtual 后的实测输出（ETH/CTRL 特有信息全丢）
base: name=packet_eth, length=64
base: name=packet_ctrl, length=8
base: name=packet_eth, length=64
```

**要点**：
- 虚特性从**基类**继承下来。基类声明了 `virtual`，子类同签名方法**自动就是 virtual**，写不写都行（写上更清晰）
- **关键在基类**。基类不写 `virtual`，子类写再多也没用，父类句柄永远调父类方法

**这就是 UVM factory 的前提**：基类方法必须 virtual，工厂才能让父类句柄自动调到子类实现。

## 九、`local` 与 `protected` 的边界

| 修饰符 | 本类 | 子类 | 外部 |
| --- | --- | --- | --- |
| `local` | ✅ | ❌ | ❌ |
| `protected` | ✅ | ✅ | ❌ |
| 无（public） | ✅ | ✅ | ✅ |

**记忆**：`local` 是"**亲儿子都不给看**"，`protected` 是"**亲儿子可以看**"。

**易错点**：以为改成员的值很随意，忽略了 `protected` 只对子类开放。
`bk.color = WHITE;`（外部）会直接编译报错，即使 `bk` 是子类对象。

## 十、内存口径：累计分配 vs 当前占用

**错误直觉**："循环 4 次 `new`，那内存就是 4 次的和。"

**正确区分两个口径**：

```systemverilog
for (int i = 1; i <= 4; i++) wd = new(i);
```

| 口径 | 算法 | 结果 |
| --- | --- | --- |
| **当前占用**（display 那一刻） | 只有最后一个对象存活 | 只算 `new(4)` 那一个 |
| **累计分配**（整个执行期间） | 每次 new 的相加 | 4 个对象全算 |

**关键机制**：`wd = new(i)` 是**句柄重指向**，不是累加。
重新赋值后，前一个对象失去引用 → 成为垃圾等 GC。
"display 那一刻"能访问到的只有 `wd` 当前指向的那一个。

**反证实验**：把每个新对象都 `push_back` 到队列（保留引用），4 个对象就都能存活。
说明"消失"不是因为 new 没生效，而是**失去了唯一引用**。
