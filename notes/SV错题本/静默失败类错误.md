> 前两类各有排查手段：书写类看**编译报错**，理解类靠**脑内模型**。
> 这一类两者都失效 —— **编译 0 错 0 警、运行不报错，但结果就是错的**，
> 或者你**以为自己验证过了，其实日志里根本没有证据**。
>
> 这一类最危险，因为没有人会提醒你。对策只有一条：**主动把"看不见的失败"变成"看得见的失败"**。

## 一、不看返回值：三个"静默失败"的动作型函数

这一族错误的共同点：**失败时什么都不改**，于是变量保持原值，看起来像是"成功了但值恰好这样"。

| 函数 | 失败时返回 | 失败时变量/句柄 | 你看到的假象 |
| --- | --- | --- | --- |
| `randomize()` | `0` | **保持原值，不清零** | "随出来了，只是值不理想" |
| `uvm_config_db#(T)::get()` | `0` | **保持默认值** | "取到了，值就是默认那个" |
| `$cast(dst, src)` | `0` | 目标句柄**保持原值**（源为 null 时反而返回 `1`） | "转成功了" |

**实测量化（随机化的例子）**：给 `p.length = 999` 当哨兵，制造约束冲突后调用 `randomize()`：

```
[C1] before randomize: length=999
[C1] both ON  -> randomize() returned 0
[C1] after  randomize: length=999      ← 值没变！
```

> ⚠️ **为什么容易误判**：对象 `new()` 之后 rand 变量本来就是 0，
> **0 分不清"被清零"和"根本没动"**。要测"失败后变量变没变"，
> 必须先用**哨兵值**（`p.length = 777;`）或先成功随一次。

**对策（记这一条就够）**：`randomize` / `get` / `$cast` —— **凡是有返回值的"动作型"函数，都判返回值**。

```systemverilog
// ❌ 全部静默
p.randomize();
uvm_config_db#(int)::get(this, "", "cfg_val", cfg_val);
$cast(dst, src);

// ✅
if (!p.randomize()) `uvm_error("RAND", "randomize failed")
if (!uvm_config_db#(int)::get(this, "", "cfg_val", cfg_val))
  `uvm_error("CFG", "cfg_val not found")
if (!$cast(dst, src)) `uvm_error("CAST", "cast failed")
```

### 1.1 同一件事，三种写法三种"可见度"（`$cast` 类句柄实测）

| 写法 | 失败时返回值 | 失败时是否报错 |
| --- | --- | --- |
| `if ($cast(d, s)) ... else ...` | 0 | 无 |
| `$cast(d, s);`（语句形式） | 被丢弃 | `** Error: (vsim-3971) ... failed`，仿真继续 |
| **`void'($cast(d, s));`** | 被 `void'` 吞掉 | **无（Errors: 0，完全静默）** ← 最危险 |

**`void'($cast(...))` 恰恰是课本里最常见的驱动写法**（`void'($cast(rsp, req.clone()))`），
而它不是"安全写法"，而是"把失败藏起来的写法"。

> 附带纠正一条网上常见的错说法：**失败时目标句柄不会变成 null，而是保持原值**
> （本机实测：`d2==null` 为 0、`d2` 仍是原来那个对象）。
> 测这一条时必须**先给目标句柄一个合法旧值**当哨兵，否则 null 声明和 null 结果分不出来。

## 二、`covergroup` 的静默：0% 和"真没覆盖"长得一样

覆盖率报告里 `0.00%` 有两种完全不同的成因，**报告本身不区分**：

| 成因 | 表现 | 怎么区分 |
| --- | --- | --- |
| **压根没被采样**（漏 `new()`、漏 `sample()`、组件没被创建） | 全 0% | 看日志里有没有采样痕迹；破坏性实验（注释掉 `sample()` 再跑） |
| 真的没覆盖到 | 全 0% 或部分 0% | 结合激励判断：这次激励能不能打到这个 bin |

> **本机实测的坑（10-02 作业）**：`a`/`b` 从未赋值、`cvg = new()` 之后从未 `sample()`
> → 覆盖率 0，**不给任何提示**。

**口诀**：看到某个 covergroup 全 0，**先确认它有没有被采样**，再谈"覆盖够不够"。

## 三、"打印了"≠"验证过了"：日志里必须有值

**错误写法**（本次作业真实出现）：

```systemverilog
uvm_config_db#(int)::get(this, "", "cfg_val", cfg_val);
`uvm_info("my_com", "get cfg_val accessfully", UVM_LOW)   // ❌ 固定字符串，没有值
```

这条日志**证明不了任何事**：取到的是 42、0、还是根本没取到，从日志上看不出来。

```systemverilog
// ✅ 把值打进消息，日志才有证据力
`uvm_info("BUILD", $sformatf("cfg_val = %0d", cfg_val), UVM_LOW)
```

**推广**：验收标准要写成**可核对的数字** —— 不是"打印了那条消息"，而是"打印出 `cfg_val = 42`"。

## 四、统计口径自己骗自己

```systemverilog
// ❌ run_total 从没累加，打印永远是 0（而且没人会发现）
$display(" samples = %0d", run_total);

// ❌ 报错信息里的 i 从没自增 —— 出错时永远指向"第 0 次"，误导排查方向
if (!p.randomize()) $error("randomize failed at %0d", i);
```

**对策**：**每个计数器都要问一句"它在哪里被 +1"**；报错信息里出现的每个变量，都要确认它有正确的取值来源。

## 五、约束/数组的静默坑

| 场景 | 现象 | 对策 |
| --- | --- | --- |
| `rand` 动态数组不约束 `size` | `randomize()` 返回 **1（成功！）**，但 `size = 0` | 必须写 `payload.size() inside {[4:64]};` |
| `size = 0` 的连带后果 | 0 落不进任何长度 bin → `cp_len` / `cross` **全 0** | 破坏性实验：注释掉 size 约束跑一遍，亲眼看 0 |
| 固定尺寸非打包数组的**常量越界访问** | Questa **不报错** | 用 `foreach` / `$size()` 自保 |

## 六、"空句柄"的两种表现（别混）

| 情况 | 表现 |
| --- | --- |
| 漏 `new()` 又去调方法（如 `cg.sample()`） | 空句柄操作 → **通常报错/崩**（不是静默） |
| 组件**从未被创建**（`create` 写错/漏写） | 组件不存在 → 它的 phase 一次都不跑，**静默** |

> 所以"忘了 `new()` → 覆盖率恒为 0 且不报错"这个说法不够精确：
> **真正静默的是"压根没人调用 `sample()`"或"组件根本没被创建"。**
> 这一条建议自己用破坏性实验钉死，别背结论。

## ✅ 自问清单：三问

写完任何一段验证代码，问自己三个问题：

- [ ] **这个函数的返回值我判了吗？**（`randomize` / `get` / `$cast` 三兄弟）
- [ ] **这条日志里有值吗？**（证明的是"跑到了"，还是"结果是对的"？）
- [ ] **这个 0 / 全 0%，是"真的是 0"，还是"根本没跑"？**

补充项：

- [ ] 每个计数器都在哪里被 `+1`？报错信息里的变量都有正确取值来源吗？
- [ ] `ret = 0` 是"失败"，还是"失败后保持了原值"？我有没有先放**哨兵值**？
- [ ] 覆盖率 0% 时，我确认过 `covergroup` 是否 `new()`、`sample()` 是否被调用、组件是否被创建？
- [ ] 我用的验收标准是"可核对的数字"吗（`cfg_val = 42`），而不是"有没有那条消息"？
